# README: C2M2 v2.1 shell


**Status:** Finalized

*A guide to importing and using the provided framework shell in Vanta*

---

## 1. Introduction

- **What this document is:** A guide to help customers upload the C2M2 (Cybersecurity Capability Maturity Model) v2.1 framework shell into Vanta as a Custom Framework.
- **Who it's for:** Customer security and compliance team members; an engineering background is not necessary to implement this shell.
- **Outcome:** By the end of this guide, the customer will have implemented the C2M2 v2.1 framework shell in their Vanta instance, together with controls that are ready to be mapped to tests, policies, and documents.
- **Note:** This framework shell is provided at no cost and is intended only as a starting point. It does not constitute official compliance guidance or a guarantee of a particular C2M2 maturity level.

---

## 2. What Is a Framework Shell?

- **Definition:** A framework shell is a free-to-use, not-for-sale compliance framework structure that can be uploaded into Vanta. It can be used by customers who have purchased the Custom Frameworks feature.
- **Purpose:** Gives customers a head start in creating their own framework. The shell can be used as an initial analysis of the authoritative source documents (i.e. the documents from the body that officially creates the standard).
- **Scope:**
  - The framework structure and controls (356 practices across 10 domains) derived from the C2M2 v2.1 model published by the U.S. Department of Energy (DOE).
  - A "Readme" document explaining how to implement the shell (this document).
- **Exclusions / What it does not include:**
  - Policy templates or addendums which may be required to satisfy C2M2 practices.
  - Document placeholders which may be required to satisfy C2M2 practices.
  - Pre-mapped Vanta evidence including tests and documents (these need to be added by the customer or a partner).
  - Interpretation or guidance from Vanta on how to implement practices or what MIL to target.
  - Official compliance guidance or a guarantee of any particular C2M2 maturity indicator level (MIL).
  - Ongoing maintenance and support, e.g. in the form of guaranteed updates (because the framework shell is a free template and not an official product, Vanta does not guarantee its completeness, accuracy, or ongoing maintenance related to future revisions made by DOE).

## 3. How the Shell Was Created

- **Source:** Controls were extracted from the following official document:
  - U.S. Department of Energy, *Cybersecurity Capability Maturity Model (C2M2), Version 2.1*, June 2022.
- **Licensing and attribution:** The C2M2 model is a work of the U.S. federal government, published for free public use. This shell reformats that publicly available content into Vanta's CSV import format; it is not an official DOE product, and DOE has not reviewed or endorsed it. If you redistribute or adapt this shell, please retain attribution to the U.S. Department of Energy as the source of the underlying C2M2 model.
- **Methodology:**
  - Each control corresponds to one C2M2 practice, taken directly from the DOE model text (`Practice Text` → `Description`, `Help Text` → `Note`). The original wording was preserved.
  - Each control's `UniqueID` is the practice's C2M2 reference notation prefixed with `C2M2-`, e.g. `C2M2-ASSET-1a` refers to practice **a** of Objective 1 (*Manage IT and OT Asset Inventory*) in the ASSET domain. This is the same notation DOE uses to cross-reference practices elsewhere in the model.
  - Each control's Maturity Indicator Level is preserved in the `MIL` field as `MIL1`, `MIL2`, or `MIL3`.
  - Each control is tagged with its C2M2 domain (`C2M2 Domain`, e.g. `ASSET`) and with the closest built-in Vanta control domain (`Vanta Domain`), so controls can be filtered/grouped in Vanta by either taxonomy. Because some C2M2 domains span more than one Vanta domain concept (for example, ASSET covers asset, change, *and* configuration management), the `Vanta Domain` mapping is an approximation — review it and adjust to fit your organization's taxonomy if needed.
  - In the framework file, each Objective becomes a requirement (e.g. `ASSET-1`) named after its official DOE objective title (e.g. *Manage IT and OT Asset Inventory*), and each Domain becomes a section (e.g. `ASSET` / *Asset, Change, and Configuration Management*).

## 4. Importing the Framework Shell into Vanta

### Prerequisites

- Framework shell (folder or zip) which consists of these files:
  - **`C2M2_v2.1_controls upload.csv`** — Contains the 356 C2M2 v2.1 practices as controls.
  - **`C2M2_v2.1_framework upload.csv`** — Defines the framework structure, sections, and mapping to Control IDs.
  - **README** — This file, which contains context and guidance for a Vanta user.
- Access to the Vanta environment with Admin permissions (to be able to upload controls and frameworks).
- Licence to use Custom Frameworks in Vanta.


### Step 0: Create Required Custom Fields

The controls file includes two columns that don't correspond to built-in Vanta control fields. **Create these custom fields on Controls in Vanta before importing the Controls CSV**, or those columns will have nowhere to map to:

- **`C2M2 Domain`** — a text or single-select custom field (values like `ASSET`, `THREAT`, `RISK`, etc.).
- **`MIL`** — a **multiselect** custom field (values `MIL1`, `MIL2`, `MIL3`).

`Owner` and `Vanta Domain` (control domain) use Vanta's built-in fields, so no setup is required for those.

### Step 1: Import the Controls

- Navigate to Controls.
- Select Import Controls.
- Upload `C2M2_v2.1_controls upload.csv`.
- Select Import.
- Further guidance can be found here:
  - Custom Controls | Vanta Help Center
  - Video tutorial - Uploading Custom Frameworks

### Step 2: Import the Framework

- Navigate to Frameworks in Vanta.
- Select Import Framework.
- Upload `C2M2_v2.1_framework upload.csv`.
- Select Import.
- Confirm that the framework structure appears correctly in Vanta (this should take a few minutes to appear correctly). You should see 10 sections (domains) and 43 requirements (objectives).
- Further guidance can be found here: Creating Custom Frameworks | Vanta Help Center

## 5. Next Steps (following the Import)

> 💡 **Recommendation:** Work with a Vanta partner to ensure accurate mappings. Your CSM can recommend a partner familiar with both C2M2 and Vanta.

### Assign Control Owners

- The `Owner` field is left blank on import. Assign an owner to each control so accountability is clear before you begin mapping tests, policies, and documents.

### Create Required Policies or Documents

- C2M2 practices reference various organizational artifacts (e.g. a documented cyber risk management strategy under RISK, a threat profile under THREAT, an inventory of IT/OT assets under ASSET). Where the customer has deemed necessary, they should create or update the relevant policies and documents to satisfy these practices.
- Once created, map the relevant C2M2 controls (by `UniqueID`) to those policies and documents.
- Further guidance can be found here:
  - Creating Custom Policies | Vanta Help Center
  - Custom Mapping Controls to Policies | Vanta Help Center

### Create Mapping of Controls to Tests

- To get the most out of using a framework in Vanta, the customer should add test mappings that will add automation based on the integrations enabled in their Vanta instance. Vanta recommends customers take a balanced approach to mapping and avoid overmapping tests if they don't have a significant impact on the practice being implemented.
- Note: Customers on growth plans can use AI to discover matching tests and documents.

### Decide on a Target MIL

- C2M2 practices are organized by Maturity Indicator Level (MIL1–MIL3). Many organizations don't need to fully satisfy MIL3 for every domain — use your risk profile to decide which domains warrant a higher target MIL, and use the `MIL` custom field to filter and report progress toward that target.

> ⚠️ **Reminder:** The framework shell provides only structure and practice-level controls. Customers remain responsible for ensuring their policies, documents, and test mappings meet their targeted C2M2 maturity level.

## 7. FAQ

**Q: Do I need to be technical to use this?**
A: No. Uploading the CSV files and reviewing the framework is straightforward and can be done via the UI.

**Q: Does this framework shell mean I've achieved a specific C2M2 MIL?**
A: No. The shell gives a customer the structure and DOE's practice text, however achieving and evidencing a given maturity level requires relevant policies, tests, and documents to be mapped to the controls, and self-evaluated against DOE's MIL criteria.

**Q: Does Vanta have C2M2 out-of-the-box?**
A: Vanta offers 40+ out-of-the-box frameworks with full mappings and test automation. C2M2 is not currently one of them — it is provided as a free-to-use starting point for customers using Custom Frameworks.

**Q: Can Vanta automatically test all C2M2 practices?**
A: No. Some practices can be covered by automated Vanta tests, while others require manual documentation or attestation. The customer remains fully responsible for selecting the correct mappings for this framework.

**Q: Why does a practice's `Vanta Domain` not match what I expected?**
A: Several C2M2 domains cover more ground than any single Vanta domain enum captures (e.g. ASSET covers asset, change, and configuration management together). The mapping picks the closest single match; feel free to override it for individual controls.

**Q: Who can help me complete this process?**
A: Vanta partners can help with mappings and audit readiness. If the customer would like assistance finding a Vanta partner, please reach out via the CSM.
